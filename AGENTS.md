# Protez: правила для агентів

Працюй із кореня цього Git-репозиторію. Налаштування середовища — у [README](README.md).

## Робота

- Не вигадуй терміновості й не перелічуй відкинуті варіанти.
- Роби найменшу зміну, що виконує запит. Перед редагуванням визнач поведінку, яку потрібно зберегти. Перед завершенням звір diff: кожна зміна має виконувати вимогу або усувати підтверджену причину дефекту. Зберігай сторонні зміни й форматування.
- Візуальні референси застосовуй до зазначених користувачем властивостей. Зберігай чинне компонування, responsive-поведінку й взаємодії, якщо запит не потребує їх зміни.
- Для виправлення дефекту спочатку відтвори його та встанови причину. Зміни CSS, налаштувань компонента й обробників подій обґрунтовуй цією причиною; перевіряй результат реальною взаємодією.
- Уточнення та ручні корекції користувача включай у поточні критерії приймання. Якщо вони суперечать попередньому рішенню, керуйся останньою явною вказівкою.
- Не змінюй TODO без прямої вказівки користувача.
- Делегуй незалежні підзадачі, коли це допомагає; перевіряй результати й узгоджуй їх перед завершенням.
- Використовуй наявні придатні компоненти й абстракції. Нові залежності та узагальнення додавай лише під конкретну поточну потребу.
- Називай нові змінні й параметри змістовно. Старі скорочення не перейменовуй заради косметичного прибирання; зовнішні поля можна локально alias-ити зі збереженням контракту.
- Не додавай пояснювальних коментарів у код, стилі чи верстку. Виражай намір назвами й структурою; зберігай наявні коментарі, необхідні директиви та ліцензії.
- Документацію для агентів тримай короткою. Кожен факт має одного власника; в інших місцях посилайся на нього. Змінив шлях або контракт — онови відповідне керівництво в межах задачі.

## Контекст

Перед плануванням, реалізацією чи рев’ю обери потрібні точки входу в [context-map](.agent-guidance/context-map.md). Прочитай цільову реалізацію; для спільних змін також перевір споживачів.

- Для локалізації, контенту, навігації, CMS, статистики, assets, API чи SEO прочитай відповідний розділ [data-map](.agent-guidance/data-map.md).
- Перед зміною коду обери перевірки з [testing](.agent-guidance/testing.md). Для документації використовуй рядок про документацію.
- Перед завершенням звір кожну суттєву вимогу запиту й уточнення користувача з результатом та доказами перевірки. Усунь пропуски в дозволеному обсязі; повідом виконані перевірки та неперевірені вимоги.
